# Complete Flow

## 1. Docker

Purpose:

> Package an application with all dependencies.

Produces

```text
Dockerfile
      │
      ▼
Docker Image
      │
      ▼
Docker Container
```

Docker only knows:

> Run ONE container.

Docker knows nothing about:

* Scaling
* Self healing
* Load balancing
* Scheduling
* Rolling updates

That is Kubernetes' job.

---

# 2. Kubernetes

Purpose:

> Maintain the desired state automatically.

Instead of saying

```text
Run payment container
```

we declare

```yaml
replicas: 5
```

Kubernetes continuously asks

```text
Desired Pods = 5

Actual Pods = ?

Match them.
```

This idea is called

> Declarative Infrastructure

---

# 3. Pod

Smallest deployable unit.

Not

```text
One Container
```

Instead

```text
Shared Environment
```

```text
Pod

├── Container A
├── Container B
└── Container C
```

A Pod provides

* Shared IP
* Shared localhost
* Shared volumes
* Shared lifecycle boundary

Pods are

* Disposable
* Ephemeral

Never depend on Pod identity.

---

# 4. Multiple Containers

One Pod can contain

```text
Payment App

+

Envoy

+

Fluent Bit

+

Vault Agent
```

Each has

One responsibility.

---

Purpose

Instead of

```text

TLS

Retry

Metrics

Logging

Authentication
```

Use

```text

↓

Envoy

↓

Network
```

Examples

* Envoy
* Fluent Bit
* Vault Agent
* Metrics exporter

# 8. Scheduler

Job

Find best node.

Pipeline

```text

Node Selection
```

Filtering

Can this Pod run?

Checks

* CPU
* Memory
* Affinity
* Taints
* Storage
* Labels

Scoring

Among valid nodes

Which is best?

---

# 9. kubelet

Runs on every Worker Node.

Responsibilities

* Watch assigned Pods
* Pull images
* Start containers
* Restart failed containers
* Execute probes

Never schedules Pods.

# 10. Health Checks


* No restart
* Removed from Service

```text

```

Failure

Restart container.

Important

# Core Architectural Principles (The Most Important Part)

Everything you've learned can be reduced to these principles:

| Principle                                      | Examples                                                                                              |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| **Declarative Desired State**                  | Deployment, HPA, Istio                                                                                |
| **Reconciliation Loop**                        | Controllers constantly match actual to desired state                                                  |
| **Single Responsibility**                      | Deployment, Service, Scheduler, kubelet, Envoy                                                        |
| **Separation of Concerns**                     | Business logic vs infrastructure, Control Plane vs Data Plane                                         |
| **Loose Coupling**                             | Service instead of Pod IP, ConfigMap instead of hardcoded config, Sidecars instead of networking code |
| **Ephemeral Compute, Persistent Data**         | Pods vs Persistent Volumes                                                                            |
| **Stable Abstractions over Dynamic Resources** | Service → Pods, StatefulSet → Stable identity                                                         |
| **Policy over Implementation**                 | RBAC, NetworkPolicy, Istio routing rules                                                              |
| **Transparent Infrastructure**                 | kube-proxy, Envoy, DNS, Ingress hide complexity behind simple APIs                                    |
